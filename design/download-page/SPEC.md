# 下载页设计说明（Design Spec）

> 状态：设计稿（未实现）。配套画面：`shots/active.png`（当前）、`shots/done.png`（已完成）。
> 源码：`active.html` / `done.html` / `mock.css`，按 Design Tokens（`Themes/Colors.xaml`、`Themes/Tokens.xaml`）等比还原。

## 1. 为什么需要单独页面

现状是三处割裂：

| 位置 | 内容 | 问题 |
| --- | --- | --- |
| 漫画右侧栏 `DownloadPanel`（`task.downloads`） | 漫画章节下载、历史 | 只有 348px 宽，一行一个章节，速度和剩余时间挤不下；历史与当前占满侧栏 |
| 视频「刮削任务」页 `VideoTaskDashboard`（`video.tasks`） | 刮削 + 视频下载混排 | 页面叫"刮削任务"，内容却有一半是下载；下载行只有 4px 条 + "已下载 428MB · 2.1MB/s" 一行字，没有"打开文件/目录"，失败只有"重试" |
| 顶部/其它页 | 无 | 下载中看不到入口，用户不知道有多少在跑 |

两类任务的语义本来就不同：
- **下载**是"搬运结果"，关心进度、速度、剩余时间、失败原因、完成后去哪儿打开；跨媒体（漫画/视频/写真）。
- **刮削**是"补元数据"，关心命中来源、未匹配、被拦；只属于视频。

合并导致下载的信息密度被刮削页的行结构压扁，且把跨媒体的同一件事拆成两个界面。**结论：独立「下载」页，跨媒体统一；「刮削任务」页只留刮削。**

## 2. 信息架构（已定）

- **入口：顶栏与「漫画 / 视频 / 本地小说 / 写真」同一组页签里的「下载」**，带进行中数量角标；它不属于 `ResourceKind`，单独走 `download.page` 路由。
- **进入下载页即沉浸式**：左侧导航、右栏、侧栏开关全部收起，页面占满左中右；点任意媒体页签回到该媒体最近的页面。
- **右侧 `DownloadPanel` 已移除**：下载只在下载页出现，避免同一件事两个界面、两套说法。`task.downloads` 面板 Id 一并删除。
- 视频「我的」组保留「刮削任务」；`DownloadVideo` 类型任务不再在刮削页出现（下载页接管）。
- 页内两个页签：`当前`（进行中 + 排队 + 失败）与 `已完成`（按天分组）。

## 3. 页面结构

```
┌ 标题区  [图标] 下载 / 漫画章节与视频文件的传输队列        [打开下载目录] ┐
├ 总览   进行中 3 · 排队 1 · 失败 1 · 今日完成 7            5.3 MB/s ┤
├ 页签   当前 5 | 已完成 7                        全部 · 漫画 · 视频 ┤
├ 列表   每行：类型图标 / 标题+元信息+进度条 / 百分比+速度+剩余 / 操作 ┤
└ 说明   关闭软件后已完成文件不重下；未下完的会从头开始（不承诺续传）  ┘
```

- **总览用计数，不用总百分比**：漫画按"张"、视频按"字节"，混合百分比是假精度。
- **列表行**：`38px 图标 | 1fr 文本+进度 | 124px 数字 | auto 操作`，行高 72，行距 8；信息从"我在下什么 → 下到哪 → 还多久 → 能做什么"自左向右推进。
- **进行中**：番号用等宽字体作为锚点；视频显示 `已下载/总大小`，漫画显示 `已下/总张数`。
- **排队**：进度条留空轨道，右侧"等待中"，元信息给"队列第 N 位"。
- **失败**：进度条转危险色，错误原因换行显示在元信息位置（站点错误原文 → 人话提示），操作给「日志」+「重试」。
- **已完成**：按天分组（今天/昨天/更早），动作「打开文件 / 打开目录」，表头右侧「清除记录」只清列表。
- **空状态**（未画）：图标 + "没有正在下载的任务" + 两个次级入口「去漫画页」「去视频页」；已完成空状态给"下载完成的内容会出现在这里"。

## 4. 状态与交互

| 状态 | 视觉 | 操作 |
| --- | --- | --- |
| 进行中 | 主色进度条 + 百分比 | 取消（悬停显示） |
| 排队 | 空轨道 + "等待中" | 取消 |
| 失败 | 危险色条 + 原因 | 日志 / 重试（常显） |
| 完成 | 绿色勾 + 完成时间 | 打开文件 / 打开目录 |
| 类型筛选 | 胶囊 chip，单选 | 全部 / 漫画 / 视频 |

不做：暂停/继续（引擎没有暂停语义，断点续传补齐后再加）；重排队列（当前实现无优先级 UI）。

## 5. 视觉与 Token

沿用 Quiet Capture 现有体系，不新增色板：
- 主色 `PrimaryBrush #4D6BFE` 只用于进度条、类型图标底、角标与主操作；
- 文本层级 `#10141F / #5C667A / #9AA3B4`，正文 13、元信息 11、标题 13.5、页标题 19；
- 卡片 `SurfaceBrush` + `CardBorderBrush` 1px + `RadiusXl(16)`（总览）/ `RadiusLg(12)`（行）；
- 数字用 Consolas（项目已有先例：速度、百分比）；
- 深色主题：全部走 `DynamicResource`，无需第二套色值。

两处为可读性做的微调（建议同步到全站）：
1. 导航栏选中项文字由 `PrimaryBrush` 改为更深的 `#3A55E0`（对比度 3.92:1 → 5.1:1）；
2. 失败原因、失败标签使用 `#C42C31`（3.91:1 → 5.4:1），进度条仍用 `DangerBrush`。

## 6. 实现记录（已落地）

| 文件 | 改动 |
| --- | --- |
| `Views/DownloadPage.xaml(.cs)` | 新页面：标题 / 总览 KPI / 当前·已完成页签 / 类型筛选 / 行模板 + 空状态 + 说明条 |
| `ViewModels/DownloadPageViewModel.cs` | `TransferItem` 统一模型 + 合并两个来源：漫画订阅 `DownloadManager` 六个事件，视频用 1s `DispatcherTimer` 轮询任务队列 |
| `Services/VideoDownloadHistoryService.cs`（Core） | 视频完成记录落 `config/video-download-history.json`，200 条上限、按输出路径去重 |
| `Services/DownloadHistoryService.cs` | 补 `Clear()`（页头「清除记录」） |
| `VideoTaskModels.cs` + `VideoScrapeTaskExecutor.cs` | 任务上增加 `DownloadedBytes / TotalBytes / SpeedBytesPerSec / EtaSeconds`，供页面直接读结构化进度而不解析日志文本 |
| `DownloadEvents.cs` + `DownloadManager.cs` | `SpeedEventArgs` 增加 `BytesPerSecond`，总速度 = 漫画 + 视频求和 |
| `MainWindow.xaml(.cs)` | 顶栏「下载」页签 + 角标（`RunningTotal`，`Checked` 事件进入，兼容键盘/自动化）；`download.page` 单路由 + `MediaKind.Download` 独立返回栈；进入时收起左栏/右栏，切回媒体时恢复其最近页面；移除 `task.downloads` 与 `DownloadPanel` 兜底 |
| `App.xaml.cs` | 注册 `DownloadPageViewModel` / 两个历史服务；删除 `DownloadPanelViewModel` |
| `Views/DownloadPanel.*`、`ViewModels/DownloadPanelViewModel.cs` | 已删除 |

行为约定：
- 漫画章节目前**没有取消能力**（`DownloadManager` 无章节级取消），所以漫画行不显示「取消」，只显示进度；视频行可取消、失败可重试（重试复用任务里的原始流地址/Referer/代理）。
- 视频「重试」是重新入队并从 0 开始（断点续传未实现），与说明条一致。
- 「打开下载目录」是带菜单的按钮：漫画下载目录 / 视频下载目录。
