# 短剧页接入方案：西瓜短剧（xiguaai.net / `*.glyxnzmv.cc`）

> 目标：在 ResourceGrab 中新增一级页面「短剧」，数据源为西瓜短剧（用户给定 `https://pu2x.glyxnzmv.cc/`，实测与 `https://xiguaai.net/` 同一站点，见 2.2）。
> 状态：**已实现（P0–P3 全部落地）**，见文末「九、落地情况」。
> 依据：2026-11-02/03 对目标站点的实测（列表 / 详情 / 播放三类页面 + m3u8 与分片逐项验证）+ 对本仓库源码的实地核对。

---

## 一、结论速览

**能做，而且比接入 MissAV 简单。** 站点是纯服务端渲染 HTML（无 JS 依赖、无 SPA、无需登录即可播放），AngleSharp 直接可解析；播放是标准 HLS，复用仓库现成的 `OnlineVideoPreviewPlayer`（Flyleaf）即可，**连 HlsLocalRelay 都不需要**。

实测三条链路全部打通：

| 能力 | 状态 | 依据 |
| --- | --- | --- |
| 列表（最新 / 推荐 / 频道 / 标签 / 排行） | ✅ 服务端直出 HTML，带分页 | `/newest/`、`/recommend/`、`/ai-duanju/`、`/tag/{slug}/page/{n}/`、`/ranks/hot/` |
| 搜索 | ✅ `/search/{kw}/{n}/`，响应含总条数 | 实测「妈妈」→ `data-track-search-total="27"`，2 页 |
| 详情（简介 / 评分 / 标签 / 选集） | ✅ 单页含全部字段与集数 | `/detail/5033/` → 6 集、261 秒、8 个标签 |
| 播放直链（m3u8） | ✅ 逐集可取，AES-128 HLS | `/video/{id}/play-frame/?ep={n}` 首个 `[data-play-slide]` 的 `data-play-src` |
| **下载到本地（m3u8 → mp4）** | ✅ ffmpeg 实测跑通 | 第 1 集 46.7 MB / 261.5 秒 / 720×1280，见第六节 |
| 是否需要 Referer / Cookie | ❌ 都不需要（仅需浏览器 UA） | m3u8 / key / 分片三种组合（无头、仅 UA、UA+Referer）全部 200 |
| 是否需要 WebView2 / 浏览器渲染 | ❌ 不需要 | 抓到的 HTML 已含全部卡片与选集节点 |

**三个真实风险**（都有对策，见第六节）：

1. **域名是随机子域且会轮换** —— 用户给的 `pu2x.glyxnzmv.cc` 只是当前线路之一，站内 `/go-home/` 就是官方线路页（实测列出 `q4yiu2` / `a3kpa` / `v4j6t` / `w0kn4s` 等同域子域 + `xiguaai.net` + `xiguadj.co`）。必须做成可配置 + 可自发现，不能硬编码。
2. **Cloudflare 按 UA 拦截** —— 用 `Python-urllib/3.13` 请求直接 **403**，浏览器 UA 才是 200。项目已有统一 UA 常量与 curl-impersonate 兜底，可直接接上。
3. **m3u8 与封面 URL 是带 `auth_key` 的签名地址，短时有效** —— 每次播放前必须实时换，**绝不能缓存 m3u8**；封面同理（内存缓存 512 张的 `ImageLoader` 够用，但不要落盘长期复用）。

**改造量**：约 **3.5～4 人日**（数据层 1.5 + 界面 2 + 播放联调 0.5），新增 ~8 个文件、改 6 处既有文件。

**关键取舍：建议新增一级类型「短剧」，而不是塞进现有「视频」。**
现有 `视频` 是「本地视频库 + 番号刮削」体系（`VideoItem` / 番号解析 / NFO / 刮削队列），短剧是「在线流媒体 + 剧集选集」，数据模型与交互都不同。硬塞会把已经 143KB 的 `VideoView.xaml.cs` 变成第三个平行实现（该文件里已经并存了「在线搜索」和「本地视频库」两套逻辑）。新增一级类型的成本其实更低：`MediaKind` 全仓只被 2 个文件用到（见 4.2），扩展面很窄。

### 2.2 反爬与域名

**Cloudflare 前置**（响应头 `server: cloudflare`），按 UA 白名单拦截：

| 请求 | 结果 |
| --- | --- |
| `User-Agent: Python-urllib/3.13` | **403 Forbidden** |
| 无 UA / 浏览器 UA（Chrome 131） | 200，317KB 完整 HTML |
| m3u8（无头 / 仅 UA / UA+Referer 三种组合） | 全部 **200**，字节数一致 |

**结论**：不需要 Referer、不需要 Cookie、不需要过 JS 挑战；**只需要一个像浏览器的 UA**。仓库已有 `VideoConstants.UserAgent`（Chrome 136）与 `CurlImpersonateClient` 兜底，正好覆盖。

> ⚠️ **实现期踩到的坑（2026-11-03，别再踩第二次）**：站点对**重复的请求头**极敏感。
> 当 `HttpClient.DefaultRequestHeaders` 里已有 `User-Agent`，而逐请求又用 `request.Headers.TryAddWithoutValidation("User-Agent", ...)` 加一遍时，
> 站点返回 **HTTP 200 + 645 字节的"地址发布页"**（`publish.js` 动态跳转页），
> 表现为"请求成功但列表永远为空"，**不报错**、日志只有一句"返回空内容"。
> 正确做法：补头前先判断客户端是否已有默认值（见 `XiguaDramaHttpClient.GetOnceAsync`）。
> 这个 bug 当时代译、单测、夹具测试全绿——只有打真实站点才暴露。

**域名轮换**是本源最大的不稳定因素。`/go-home/` 是官方「最新地址发布页」，结构化程度很高，可直接解析：

### 2.5 播放链路真相

对 `data-play-src` 逐层展开实测：

```
master m3u8 (yd-hls.hzjvlo.cn)   ← 每集一个，含 auth_key 签名
 ├─ #EXT-X-KEY:METHOD=AES-128, URI="https://tp6.drleao.cn/.../crypt.key?auth_key=..."
 └─ 分片（绝对 URL，另一个 CDN 域 tp6.drleao.cn，同样带 auth_key）
```

| 观测 | 结果 | 含义 |
| --- | --- | --- |
| m3u8 不带 Referer | 200 | 无需防盗链头 |
| key / 分片不带 Referer | 200（16B / 1.4MB） | 无需中继注入 Referer |
| 分片在**另一台主机** | `tp6.drleao.cn` ≠ `yd-hls.hzjvlo.cn` | `HlsLocalRelay` 只改写同主机的 URI，这里会走"绝对 URL 直连"分支 → 也能播，但毫无收益 |
| 加密 | `METHOD=AES-128` + `IV` | FFmpeg/Flyleaf 原生支持，key 由播放器自行 GET |
| `auth_key` 时效 | 同一 URL 约 5 分钟后仍 200；但每次请求 play-frame 都会换新签名 | **每次播放前重新取 play-frame**，禁止缓存 m3u8 |
| 封面 `auth_key` | 与 m3u8 同期签发（约 2 小时） | 封面可内存缓存，不要落盘长期复用 |

> 因此播放可以直接走：
> `new OnlineVideoPreviewPlayer { StreamUrl = master, Referer = "" }`
> 现有 `OnlineVideoPreviewPlayer` 的契约就是 `StreamUrl + Referer`，**零改动**即可用；`HlsLocalRelay` 不需要。

**逐集取流成本**：每集 1 次 `play-frame` 请求（约 200KB HTML）。6 集剧即 6 次请求，串行 2～3 并发足够；**没有批量 API**（`/api/` 在 robots 中禁止，且实测只找到埋点接口 `/api/site/click`、`/api/videos/recommend/ref/…`，无播放列表接口）。

### 2.6 robots.txt（合规提示）

```
User-agent: *
Disallow: /admin/  /api/  /profile/  /upload/  /search/  /login/  /register/  /*?*
```

- `/search/` 与所有带查询串的 URL 对通用爬虫是**禁止**的（本工具是用户手动触发的桌面客户端，非搜索引擎爬虫；但建议默认加上 `1 请求/秒` 节流，不自建全站爬取）。
- AI 爬虫（GPTBot / ClaudeBot / PerplexityBot 等）被显式 `Allow: /`，`CCBot` / `Bytespider` 被 `Disallow: /` —— 说明站点本身对"非浏览器访问"有分层态度，进一步印证 2.2 的 UA 策略。

## 六、下载与本地库

### 6.1 结论：ffmpeg 链路已实测跑通

2026-11-03 用仓库自带的 `bin\Release\ffmpeg\ffmpeg.exe` 对第 1 集真实取流并落盘：

```
ffmpeg -user_agent "<Chrome/136>" -i "<play-frame 取到的 m3u8>"
       -c copy -bsf:a aac_adtstoasc -f mp4 out.mp4
```

| 观测 | 结果 |
| --- | --- |
| 退出码 | **0** |
| 产物 | **46.7 MB**，`ffprobe` 报 **261.5 秒**（详情页签名时长 261 秒，完全一致） |
| 编码 | h264 + aac，**720×1280 竖屏**，约 1.5 Mbps |
| 耗时 | 75 秒（走本机代理，约 0.6 MB/s；直连会更快） |
| AES-128 | **自动完成**——key 是带签名的绝对 URL，ffmpeg 自己 GET 并解密，不需要我们中转 key |
| Referer | 不需要（与播放链路结论一致） |
| 瞬时错误 | 日志里出现 `Stream ends prematurely` / `Packet corrupt` 后**自愈**，产物依然完整 |

**关键判断：不需要新写下载引擎。** `VideoDownloadService` 已经把该踩的坑都踩过——UA 透传、`-rw_timeout 15s`、`-reconnect` / `-reconnect_streamed` / `-reconnect_delay_max 5`、`.downloading` 临时文件、进度解析、失败日志中文化。短剧下载 = **组装请求 + 决定落盘位置 + 下载后校验**，三件事。

### 6.2 目录与元数据

每部剧一个文件夹，`drama.json` 是本地库的唯一真相来源（离线可读，不依赖网络）：

```
config\短剧下载\
└─ 妈妈和姐姐用了我的系统都说好\
   ├─ 妈妈和姐姐用了我的系统都说好 第01集.mp4      ← 46.7 MB / 4:21
   ├─ 妈妈和姐姐用了我的系统都说好 第02集.mp4
   ├─ … 第06集.mp4
   ├─ poster.jpg                                ← 下载时抓一次，规避封面签名过期
   ├─ ep01.jpg …                                ← 抽帧缩略图（本地卡片 / 选集用）
   └─ drama.json                                ← 元数据 + 每集状态
```

```jsonc
{
  "schema": 1,
  "id": "5033",
  "title": "妈妈和姐姐用了我的系统都说好",
  "coverFile": "poster.jpg",
  "description": "深夜，陈默贴着门缝看着冷艳的市委书记母亲…",
  "scoreText": "8.4",
  "tags": ["乱伦", "熟女", "口交", "都市", "御姐"],
  "channelName": "AI成人短剧",
  "totalEpisodes": 6,
  "updatedText": "更新至6集",
  "releaseText": "2026-10-29",
  "sourceId": "xigua",
  "fetchedAt": "2026-11-03T10:20:00+08:00",
  "episodes": [
    { "number": 1, "durationText": "4:21", "file": "… 第01集.mp4", "sizeBytes": 48934418,
      "downloadedAt": "2026-11-03T10:22:11+08:00" },
    { "number": 2, "durationText": "4:21" }        // 无 file 字段 = 未下载

```

**为什么不写 `.nfo`**：`.nfo` 是给 Kodi/Emby 的刮削格式，短剧没有番号也没有演职员体系，写出来只会是空壳。`drama.json` 自描述、易迁移，本地库直接读它。

**为什么文件名带「第01集」而不是 `S01E01`**：中文用户目录里排序/肉眼识别都更直观；真正的排序依据是 `drama.json` 的 `number` 字段（文件名字符串排序会把「第10集」排到「第2集」前面）。

### 6.4 下载流程（单集）

```
1. 详情页点「下载本集」/「下载全剧」
2. 对每一集：
   a. POST 前先查本地 drama.json —— 已存在且文件非空 → 跳过（Skipped）
   b. GET /video/{id}/play-frame/?ep={n} 取新鲜签名 m3u8    ← 绝不复用旧地址
   c. EnsureDramaFolder() + 写 poster.jpg（仅首次）
   d. VideoScrapeTaskQueue.EnqueueDownload(new VideoDownloadRequest(
          Number: 剧名, Title: $"第{n:D2}集", StreamUrl: m3u8,
          Referer: "", Proxy: 配置代理, DurationText: 该集时长,
          OutputDirectory: {根}\{剧名}))
   e. ffmpeg 落 .downloading → 成功后 ffprobe 校验时长
   f. 校验通过 → 原子改名 → 更新 drama.json（sizeBytes / downloadedAt）
3. 全部完成 → 下载页该剧行变为「完成」；本地页出现/更新卡片
```

**并发**：队列默认并发 4，但短剧单集 30–70 MB，建议 `ShortDramaDownloadService` 内部把并发压到 **2**（一次下两集），避免把带宽吃满导致播放卡顿。

**失败重试**：单集失败重下整集（ffmpeg 不支持分片级续传）；连续 2 次失败 → 该集标红，其余集继续，不整单失败。

**校验阈值**：|实际时长 − 期望时长| / 期望时长 > 5%，或实际时长为 0 → 判定失败并重下。若连续两次都对不上（源站本身就是残缺文件），保留文件但标记 `partial: true`，UI 上给一个警告角标而不是当成成功。

### 6.6 竖屏这件事必须提前说清楚

源站视频是 **720×1280 竖屏**（并不是 16:9）。影响三处：

1. **播放器**：`OnlineVideoPreviewPlayer` 是按容器铺满的，竖屏视频在 16:9 容器里会左右留黑边；建议在短剧播放页把 stage 改成 **按视频比例自适应**（`MaxHeight` 约束 + 居中），而不是死守 16:9。设计稿里 16:9 是为了版面稳定，实现时用 `Uniform` 即可。
2. **缩略图**：抽帧得到的是竖图，本地卡片 4:5 裁切没问题；但不要按 16:9 裁。
3. **抽帧参数**：`ffmpeg -ss 3 -i ep.mp4 -frames:v 1 -vf scale=360:-2 ep01.jpg`（跳过首帧黑场，取第 3 秒）。

## 七、风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| **域名轮换 / 主机失效** | 全站不可用 | 4 级解析（配置→记忆→静态列表→`/go-home/` 自发现）；UI 显式报错而不是空列表；`baseUrl` 进 `config.json` 免重编译 |
| **Cloudflare 按 UA 拦截** | 403 | 统一 `VideoConstants.UserAgent`；`IResilientFetcher` 403 时降级 curl-impersonate；请求间隔默认 1000ms |
| **签名 URL 过期** | 播放 403 / 封面裂图 / 下载失败 | m3u8 **绝不缓存**，每次播放或下载前实时取 play-frame；封面下载时落到本地 `poster.jpg`；缓存只存"剧集 ID + 集号"，不存 URL |
| **HTML 结构改版** | 解析全空 | Parser 与 IO 分离 + 夹具单测；解析结果为空时记日志并落到「解析可能失效」错误态（而不是静默空） |
| **频道页重复卡片** | 列表翻倍/重复项 | 4.3 的 `is-active` 优先 + 按 ID 去重规则（已实测覆盖） |
| **逐集取流 N 次请求** | 打开长剧详情慢 | 详情页**懒取流**：只在点某集时请求该集；不预取全部（6 集也只需 1 次） |

### 9.4 已知限制 / 后续

0. **封面是「加密图管线」——已破解并在本地解密（2026-11-03 完成）**
   站点把封面**加密后**放 CDN：`pic.drleao.cn` 返回 `Content-Type: binary/octet-stream`、
   字节熵 7.997、长度恒为 16 的整数倍、`ETag` 就是密文 md5。浏览器靠
   `/static/web/js/plugins/crypto-worker.js` 在本地解密（`lazyload.js` 的注释把这个管线讲得很清楚，
   连"不要把解密后的明文写进 IndexedDB"的理由都写了）。
   **密钥是写死在 worker 里的常量**（下划线分隔的字符码）：
   ```js
   const i0 = { mode: "CBC",
                media_key: "102_53_100_57_...",   // → ASCII "f5d965df75336270"
                media_iv:  "57_55_98_54_...",     // → ASCII "97b60394abc2fbe1"
   ```
   即 **AES-128-CBC / NoPadding**。实现见 `Core/Services/ShortDrama/DramaCoverCipher.cs`：
   解密后按 EOI/IEND 裁掉块对齐的尾部垃圾。实测首页 6 张封面全部还原成真图（4 JPEG + 2 PNG，最大 1086×1448）。
   `DramaCoverService` 负责「下载 → 解密 → 按剧集 id 落盘缓存」（`config\drama-covers\`），
   卡片与详情页都只绑本地缓存文件路径；解密失败才回落到「确定性渐变 + 剧名首字」兜底。
   密钥参数若变更，只改 `DramaCoverCipher` 里的 `KeyText`/`IvText` 两个常量。
   验证脚本：`scripts\decrypt-site-covers.ps1` + `scripts\render-drama-cards-live-covers.ps1`。

1. **未做的入口**：追剧、观看历史（导航里已移除，避免点到死路由）；`autoDownloadNewEpisodes` 字段已留，逻辑待 P4。
2. **并发上限**：下载并发在服务内部用信号量控制（1–4），队列本身仍是全局并发，多个剧同时下载时不会互相排队。
3. **完整性校验**：当前以 ffmpeg 退出码 + 文件存在为准；`ffprobe` 时长比对（方案 6.4 的 5% 阈值）尚未接入，属下一步加固项。

### 9.5 竖屏适配与本地导入（2026-11-03 追加）

**竖屏**：西瓜的剧基本是 720×1280。原来的播放框是「宽 = 剩余列宽、高 320–480」，竖屏片塞进去两侧全是黑边。
现在 `OnlineVideoPreviewPlayer` 在首帧后读 `Player.Video.Width/Height` 暴露 `VideoAspectRatio` + `VideoAspectChanged`，
详情页按比例收缩播放框（竖屏 = 高度 × 比例并居中，横屏/未知 = 铺满）。
验证脚本 `scripts\check-drama-portrait.ps1`：竖屏 0.5625 → 180×320，横屏 1.78 → 铺满（NaN），未知 → 铺满。

**本地导入**：`Core/Services/ShortDrama/DramaLocalImportService.cs`
1. 根目录下每个子目录当一部剧（根目录自己散放视频则整体当一部）；
2. 目录名去 `【】[]()`、`全12集`、`更新至8集`、`4K/1080P` 等尾巴得到剧名；
3. 文件名认集号（`第12集` / `EP12` / `E12` / `-05` / `05`）；
4. `SearchAsync` 搜站点 → 归一化后按「全等 > 包含 > Dice 二元组相似度」打分，阈值 0.62，宁缺毋滥；
5. `MergeDetail` 拿在线元数据 → 按集号挂上本地文件名 → 写 `drama.json`（新增 `importedFrom` 字段）；
6. 封面走解密服务存 `poster.jpg`；目录登记进 `config\drama-imports.json`，`Load()` 会一并扫描。
视频文件不移动/不复制/不重命名。live 测试 `Live_Import_LocalFoldersGetOnlineInfo` 覆盖了「能匹配 + 不能匹配」两条路径。

### 9.6 下载任务归并到「下载」页（2026-11-03）

原来短剧的「下载中」列表在**本地页**，和「下载」页的视频任务重复展示。现在只保留一处：

- 本地页只显示**已下载完成**的剧集（离线播放/删除），空态文案直接指向「下载」页；
- 下载页已经会镜像队列里的所有 `DownloadVideo` 任务，短剧任务天然会出现，但需要能和普通视频区分，
  于是给 `VideoDownloadRequest` / `VideoScrapeTask` 加了一个 `Category` 字段（append-only，默认 null = 普通视频），
  由 `ShortDramaDownloadService` 传 `"shortdrama"`，队列与执行器原样透传。

下载页据此渲染：标题 `剧名 · 第N集`、副标题 `短剧 · 已下载/总量`，取消按钮走既有的 `VideoTaskId` 链路，
任务完成后行条目落到历史并由 `OutputPath` 得到该剧文件夹，「打开目录」直接进对应剧集目录。
live 用例 `Live_Download_OneEpisode_BackfillsMetadata` 里补了断言：任务的 `DownloadCategory == "shortdrama"`、
`Number == 剧名`、`DownloadTitle == 第01集`、`DownloadOutputDir` 非空。
