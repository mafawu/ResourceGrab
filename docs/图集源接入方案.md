# 图集内容源接入方案：coserslove + lovecutes

> 目标：为 ResourceGrab 新增两个 cosplay / 写真图集内容源，在界面中提供**标签 / 分类 / Coser / 下载 / 下载管理**能力。
> 状态：**方案待评审，尚未编码**。本文基于 2026-10-05/06 对两个目标站点的实地探测 + 对本仓库源码核对编写。
>
> 本文取代早先的 `coserslove图集源接入方案.md`（已合并入本文，含 lovecutes）。

---

## 一、结论速览

两个站点的**内容模型完全相同**（图集 → 图片序列，无章节），但**抓取难度天差地别**：

| 维度 | coserslove.com | lovecutes.com |
| --- | --- | --- |
| 生成框架 | Astro v6.3.1（SSG 静态） | 自定义（PHP/Go 系） |
| **详情页可访问性** | ❌ **403**（Cloudflare 拦截） | ✅ **200 直连** |
| **robots.txt** | 未探测到约束 | ✅ **`User-agent: * / Allow: /`**，仅禁 `/admin`、`/plus/count` |
| 结构化数据 | 列表页 JSON-LD `ItemList` | ✅ **详情页 JSON-LD `ImageGallery`，含全部图片 URL** |
| 图集 ID | UUID | 数字（`/article/32731/`） |
| 图片格式 | AVIF（列表页仅见 `md.` 中图） | ✅ **JPG 原始图，文件名自带序号 `-001.jpg`** |
| 图集内分页 | 单页展示全部 | `/article/{id}/page/{n}/`（如 6 页） |
| 分类 | `/category/{slug}` | `/type/{n}/` |
| 标签 | `/tag/{slug}` | `/tag/{n}/` |
| **Coser** | `/coser/{uuid}` | `/entity/creator/{slug}` |
| 额外维度 | 游戏 `/game/{slug}` | 作品系列 `franchise`、角色 `character`、专题 `topic` |
| 语言镜像 | zh / en / ja | zh / zh-hant / en / ja / th / vi |
| 站点规模 | 6902 图集 / 33.4 万图 / 338 分类 / 1951 标签 | 图集用 99+ 页 sitemap 分片（量级相当或更大） |
| **接入难度** | **高**（需过 Cloudflare） | **低**（可直连） |

**核心判断：**
- **lovecutes 是低风险源，可以立刻做**——详情页直连、robots 全站放行、图片是带序号的 JPG 原图、详情页 JSON-LD 直接给出完整图片列表。
- **coserslove 是高风险源**，成败取决于能否绕过 Cloudflare，必须先做可行性验证。

因此建议：**lovecutes 先行落地（P1），coserslove 走独立的可行性验证闸门（P0）后再决定**。两者共用同一套抽象。

## 二、站点 A · coserslove.com

### 2.1 站点性质

| 项 | 结论 | 依据 |
| --- | --- | --- |
| 内容类型 | Cosplay 图集（album → 图片，**无章节层级**） | 首页卡片、`/album/{uuid}` |
| 生成框架 | **Astro v6.3.1**（静态站点生成，服务端渲染 HTML） | `<meta name="generator" content="Astro v6.3.1">` |
| 单页应用 | 否，**无需 JS 渲染**，AngleSharp 可直接解析 | 首页 HTML 252KB 完整可读 |
| 规模 | 6902 图集 / 334611 图 / 338 分类 / 1951 标签 | 页面内 JSON-LD `description` |
| 图片 CDN | `img.coserslove.com/pic/{图集UUID}/{图片UUID}/{尺寸}.{ext}` | 列表页缩略图实测 |
| 防护 | Cloudflare **分层拦截**（见 2.4） | `window.__CF$cv$params` |

### 2.2 URL 体系

| 维度 | 列表页 | 详情/浏览页 | 分页 |
| --- | --- | --- | --- |
| 首页流 | `/` | — | `/page/{n}`（≥9 页） |
| 分类 | `/categories` | `/category/{slug}` | `/category/{slug}/{n}` |
| 标签 | `/tags` | `/tag/{slug}`（如 `/tag/baisi`） | 同上 |
| Coser | `/cosers` | `/coser/{uuid}`（**UUID 而非 slug**） | 同上 |
| 游戏 | `/games` | `/game/{slug}`（待验证） | 同上 |
| 图集详情 | — | `/album/{uuid}` | 单页全量 |
| 视频筛选 | `/albums/with-video` | `/category/{slug}/with-video/{n}` | ≥9 页 |
| 短视频 | `/reels` | — | — |
| 站点地图 | `/sitemaps/{static,taxonomy,albums/{zh\|en\|ja}-{0..3}}.xml` | — | — |

- `taxonomy.xml` **只收录 `/category/`**，标签与 Coser 详情页不在 sitemap 内 → 只能从 `/tags`、`/cosers` 列表页抓，而这两页恰好被拦。
- 图集 ID 与 Coser ID 均为 UUID（非数字），下载引擎的 `$"{SourceId}|{ChapterId}"` 映射机制已能处理（与拷贝漫画同构）。

### 2.3 数据获取路径

**通道 A — JSON-LD（推荐）**：列表页内嵌单个 `application/ld+json`，含 `ItemList` → `ImageGallery` 数组，每项有 `name` / `url` / `image`：

```json
{"@type":"ImageGallery","name":"[修修猫] 鸣潮 - 守岸人[26P - 138MB]",
 "url":"https://coserslove.com/album/4c116865-...","image":"https://img.coserslove.com/pic/.../md.avif"}
```

**通道 B — CSS 选择器（兜底）**：`href="/album/{uuid}"` + 邻接标题节点。

**标题解析规则**（固定格式，可正则拆 5 字段）：

```
[修修猫] 鸣潮 - 守岸人[26P - 138MB]
└─Coser─┘ └系列┘ └角色┘ └张数┘ └体积┘
```

### 2.4 反爬现状（**本源最大风险**）

curl + 完整浏览器头实测：

| 目标 | HTTP | 说明 |
| --- | --- | --- |
| `GET /` | **200**（252KB） | 首页直连 |
| `GET /sitemap.xml`、`/sitemaps/*.xml` | **200** | 站点地图完全开放 |
| `GET /album/{uuid}` | **403**（5.4KB 拦截页） | 详情页被拦 |
| `GET /tags` | **403**（5.2KB 拦截页） | 标签/Coser 列表页被拦 |

拦截体约 5KB，非完整 HTML → 典型 **Cloudflare managed challenge / block**。首页与 sitemap 放行、详情页与列表页拦截，说明防护**按路径或按请求指纹分层**，不是全站硬墙。

> 该站还有 AVIF 图片格式与未知的大图变体两个待确认项（见 8.2）。

## 三、站点 B · lovecutes.com

### 3.1 站点性质

| 项 | 结论 | 依据 |
| --- | --- | --- |
| 名称 | 爱妹子 · 美女写真与 Cosplay 图集 | `<title>` |
| 框架 | 自定义（非主流 SSG），**服务端渲染 HTML** | 无 generator meta |
| 防护 | 前置 Cloudflare，但**未开启挑战**；详情页 200 | `Server: cloudflare` + 实测 |
| robots.txt | **`User-agent: * / Allow: /`**，仅禁 `/admin`、`/plus/count` | 实测全文 |
| 图片 | **JPG 原图**，`/static/images/{Y}/{M}/{D}/{slug}/{名称}-001.jpg` | 详情页实测 |
| 图集分页 | `/article/{id}/page/{n}/`（示例 6 页 / 53 图） | 详情页 JSON-LD `pagination` |
| 语言 | zh / zh-hant / en / ja / th / vi（`/en/`、`/ja/`… 前缀） | 详情页分页链接 |
| 右侧栏 | 侧栏响应头 `Set-Cookie: user_segment=anon`，有 `/auth` 登录 | 响应头 |

### 3.2 URL 体系

| 维度 | 列表/索引页 | 详情页 | 备注 |
| --- | --- | --- | --- |
| **图集** | `/sort/new/`（最新）、`/sort/hot/`（热门） | `/article/{id}/`，内页 `/article/{id}/page/{n}/` | 数字 ID |
| **分类** | `/type/{n}/` | — | 数字 ID，如 `/type/9/` = 私房写真 |
| **标签** | `/tag/`（索引） | `/tag/{n}/` | 数字 ID |
| **Coser** | `/entities`、`/entities/` | `/entity/creator/{slug}/` | slug，如 `/entity/creator/mo-ji/` |
| 作品系列 | — | `/entity/franchise/{slug}/` | 如 `/entity/franchise/bi-lan-hang-xian/`（碧蓝航线 273 条） |
| 角色 | — | `/entity/character/{slug}/` | 如 `/entity/character/guang-hui/`（光辉） |
| 专题 | `/topics` | `/topic/{slug}/` | 如 `black-silk-stockings` |
| 排行 | `/rankings` | — | — |
| 搜索 | — | `/search/?q={kw}` | 200 直连 |
| 站点地图 | `/sitemap.xml` 索引 → `sitemap-{article,type,topic,tag,entity,discovery}.xml` | | article 分片 99+ 页 |

> **注意**：`/entities` 返回 301（需跟随后取 `/entities/`）；`/type/`（不带 id）返回 404，必须带数字 ID。

### 3.3 数据获取路径（**这个源最省事**）

详情页内嵌两个 `application/ld+json`，**第一个直接给出完整图片列表**：

```json
{"@type":"ImageGallery",
 "name":"[私房] 上海卿卿子 - 白虎私拍：酒店JK白虎自拍 53P22V - 私房写真 - 爱妹子",
 "description":"卿卿子在酒店镜前拍JK白虎…一共53张。",
 "keywords":"私房写真, 白虎, 学生装, 白丝, 酒店, 私拍, 视频, 大尺度",
 "numberOfItems":53,
 "pagination":{"@type":"Pagination","currentPage":1,"totalPages":6},
 "itemListElement":[{"@type":"ImageObject","position":1,
   "contentUrl":"https://www.lovecutes.com/static/images/2026/10/04/si-fang-.../...-001.jpg"}, …]}
```

第二个是 `BreadcrumbList`，给出「首页 → 分类 → 图集」路径（可直接取分类 ID）。

**关键优势：**
- `keywords` = 标签数组，`numberOfItems` = 图片总数，`pagination.totalPages` = 页数。
- `itemListElement[].contentUrl` = **图片直链**，无需二次解析。
- 图片文件名自带 `-001`、`-002` 序号 → **天然有序，不需要站点侧排序还原**（对比禁漫分块、拷贝漫画 `words[]` 重排，这里是零成本）。

**缩略图 vs 原图规则**：列表页缩略图路径为 `{原图路径}.homepage.webp`（如 `xxx.jpg.homepage.webp`），**去掉 `.homepage.webp` 后缀即原图**。

### 3.4 与 coserslove 的关键差异

| | coserslove | lovecutes |
| --- | --- | --- |
| 结构化数据位置 | **列表页**（只有摘要） | **详情页**（含全部图片） |
| 获取图片列表 | 需解析详情页 HTML（**且被 403**） | 读详情页 JSON-LD 即得 |
| 图片格式 | AVIF（可能只有中图） | JPG 原图 |
| 下载门槛 | 高 | 低 |

## 四、统一抽象设计

### 4.1 复用现有骨架

两个站都套用项目既有的「加一个新站 = 写一个实现 + 注册一行」模式，且**下载引擎与下载管理零改动**。

### 4.2 需要新增/扩展的抽象

**（1）多维度浏览抽象 `ITaxonomySource`**

现有 `ICategorySource` 只支持一层分类，无法承载标签/Coser 等维度。新增：

```csharp
public enum TaxonomyKind
{
    Category,    // coserslove /category/{slug}   lovecutes /type/{n}
    Tag,         // coserslove /tag/{slug}        lovecutes /tag/{n}
    Coser,       // coserslove /coser/{uuid}      lovecutes /entity/creator/{slug}
    Franchise,   // lovecutes /entity/franchise/{slug}   作品系列
    Character,   // lovecutes /entity/character/{slug}   角色
    Topic,       // lovecutes /topic/{slug}              专题
}

public interface ITaxonomySource
{
    /// <summary>该源支持的浏览维度（UI 据此生成导航入口）。</summary>
    IReadOnlyList<TaxonomyKind> SupportedKinds { get; }

    /// <summary>获取某维度下的全部条目（分类表 / 标签云 / Coser 列表）。</summary>
    Task<IReadOnlyList<ComicCategory>> GetTaxonomiesAsync(TaxonomyKind kind, CancellationToken ct = default);

    /// <summary>按某维度下的条目浏览图集（page 从 1 开始）。</summary>
    Task<SearchResult> BrowseAsync(TaxonomyKind kind, string id, int page, CancellationToken ct = default);
}
```

**（2）`ComicSourceInfo` 扩展**

```csharp
// 新增
public bool IsGallery { get; init; }                    // 图集模型：UI 隐藏"章节"措辞
public IReadOnlyList<TaxonomyKind> Taxonomies { get; init; } = Array.Empty<TaxonomyKind>();
```

导航由 `MangaNavSectionProvider` 读 `Taxonomies` 生成，**不影响其他已有的 5 个源**（它们的 `Taxonomies` 为空）。

**（3）领域模型映射**

| 站点概念 | 现有模型 | 说明 |
| --- | --- | --- |
| 图集 album / article | `ComicDetail` | `IsGallery = true` |
| 图集本身 | **唯一 1 个 `Chapter`** | 无章节层级，Title 取图集名 |
| 图片 | `ImagePage` | `BlockNum = 0`（无分块重组） |
| 标签 / 分类 / Coser | `ComicCategory` | 统一为一棵树，用 `TaxonomyKind` 区分 |

### 4.3 `ComicSourceInfo` 建议值

```csharp
// coserslove
Id = "coserslove", DisplayName = "Cosers爱", IsGallery = true,
Taxonomies = [Category, Tag, Coser],
CoverHeaders = { ["Referer"] = "https://coserslove.com/" },   // CDN 防盗链
MaxImageConcurrency = 8, MaxChapterConcurrency = 2, MaxUrlFetchConcurrency = 2,

// lovecutes
Id = "lovecutes", DisplayName = "爱妹子", IsGallery = true,
Taxonomies = [Category, Tag, Coser, Franchise, Character, Topic],
CoverHeaders = new Dictionary<string, string>(),               // 无防盗链，直连
MaxImageConcurrency = 16, MaxChapterConcurrency = 3, MaxUrlFetchConcurrency = 4,
```

### 4.4 抓取层

| 源 | 通道 | 说明 |
| --- | --- | --- |
| lovecutes | **L1 HttpClient** 即可 | 详情页 200，无需指纹伪装；保留 L2 作为兜底 |
| coserslove | **必须 L2 curl-impersonate** | L1 被 403，需 Chrome TLS 指纹；L3 预留 |

两个源共用视频模块已建成的 `IResilientFetcher`（L1 → L2 → L3 自动降级 + `DomainCookieJar` 复用 `cf_clearance` + `BlockDetector` 识别拦截）。

> **需要解耦**：`MultiTierFetcher` 现在位于 `Core/Services/VideoScrape/Fetching/`，构造依赖 `VideoScrapeSettings` / `VideoScrapeAdvancedSettings`。要给它用，需把这层提升为通用 `Core/Http/Fetching/`，或为其注入一组通用抓取设置。

## 七、分阶段实施计划

### 轨道 1 · lovecutes（低风险，先行）

| 阶段 | 内容 |
| --- | --- |
| **L-P1** Core 源实现 | `Sources/LoveCutes/` 四文件；解析器以 **JSON-LD `ImageGallery`** 为主路径、CSS 兜底；用离线 HTML 样本补单元测试 |
| **L-P2** UI 接入 | `ITaxonomySource` + `TaxonomyBrowseView` 泛化；导航按 `Taxonomies` 生成；新增矢量图标 |
| **L-P3** 下载打通 | 详情页勾选 → `DownloadManager`；多页图集（`/page/{n}/`）合并为单一章节的完整图片列表 |
| **L-P4** 打磨 | 增量缓存、请求节流、失败重试 |

> lovecutes 无阻碍，可直接进入实现。

### 轨道 2 · coserslove（高风险，先过闸门）

| 阶段 | 内容 |
| --- | --- |
| **C-P0** 可行性验证（**必须先做，决定成败**） | ① 取 curl-impersonate（Windows 版）二进制，确认 `CurlImpersonateClient.Available`；② 用它请求 `/album/{uuid}` 与 `/tags`：能拿到真实 HTML → 走 L2 即可；仍 403/返 Turnstile → 需启用 **L3（FlareSolverr/无头浏览器）**，工作量与部署复杂度显著上升，**需重新评估是否继续**；③ 确认大图变体（`md.avif` 是否有 `lg.`/`orig.`/`md.jpg`）；④ 确认搜索端点；⑤ 抓 `/tags`、`/cosers` 确认真实结构（sitemap 未收录）；⑥ 确认 Referer/Cookie 要求 |
| **C-P1** Core 源实现 | `Sources/CosersLove/` 四文件；复用轨道 1 已建好的 `ITaxonomySource` |
| **C-P2** UI 接入 | 仅需在常量层配置 `Taxonomies`，导航自动生成（轨道 1 的泛化已覆盖） |
| **C-P3** 下载 | 处理 AVIF 输出与防盗链 |

> 轨道 1 建成的抽象是为轨道 2 铺路的——如果 coserslove 的 P0 失败，轨道 1 的成果不受影响。

### 交付物（每个阶段）
- C-P0 / L-P1 均需产出《链路探测报告》+ 样例 HTML/JSON 样本，作为解析器开发与测试的输入。

## 八、风险与开放问题

### 8.1 风险（按严重度）

### 8.2 开放问题（需确认）

1. **AVIF 输出**（仅 coserslove）——选项：(a) 原样存 `.avif`（零成本，兼容性一般）；(b) 引入 AVIF 解码（`Magick.NET` 或 ImageSharp AVIF 扩展）转 jpg/png；(c) 优先取站点 jpg 变体（C-P0 验证是否存在）。
   > 建议：先验证 (c)，不行则 (a) 保底、(b) 作为增强。**lovecutes 无此问题**（原生 JPG）。
2. **是否纳入视频维度**——coserslove 有 `/reels` 与 `with-video` 筛选；lovecutes 标题含 `22V`（视频）标记。**建议一期不做**，范围会显著扩大。
3. **是否纳入 lovecutes 的额外维度**（作品系列/角色/专题）——抽象已支持（`TaxonomyKind`），实现成本低，**建议纳入**（首页已在推荐这些维度，用户价值高）。
4. **登录 / 收藏**——coserslove 有 `/favorites`、`/wishlist`；lovecutes 有 `/auth`。**建议一期不做**。
5. **单源 exe 还是并入主程序**——推荐并入主程序；若需独立 exe，现有派生机制（覆盖 `DataDirName` + `ConfigureSources`）已支持。
