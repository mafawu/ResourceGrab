# 在线小说源 · 爱丽丝书屋（alicesw.com）可行性报告

- 目标站点：`https://www.alicesw.com/`（简体站；繁体 `alicesw.tw`，发布页 `www.asw5.cc`）
- 评估时间：2026-11-04
- 评估方式：实测抓取首页 / 搜索 / 详情 / 全目录 / 正文 5 类页面，共 30+ 次请求，核对 HTML 结构、反爬特征、限流表现

## 1. 结论

**可行，且属于"低技术难度"一类**：站点是服务端渲染的传统 PHP 模板站（diyquge 模板 + layui），正文是纯 HTML `<p>` 段落，无签名、无加密、无 JS 挑战、无需登录，`AngleSharp` 解析即可。

真正的成本不在抓，而在**把这个站点接进现有"本地小说"架构**——当前小说的阅读链路是纯本地文件（`NovelIndexService` → `NovelReaderView.LoadFile(path)`），没有任何"源"抽象。

| 方案 | 范围 | 估时（熟悉本仓库的前提下） |
| --- | --- | --- |
| A. 最小可用：在线搜书 + 单章在线阅读 | 新增 `INovelSource` + alicesw 实现 + 在线搜索页 + 阅读器在线模式 | 2–3 人日 |
| B. A + 整本导出为本地 txt（复用现有书架/索引/阅读器） | 再加导出服务与进度文件 | 1–2 人日 |
| C. 完整：分类浏览 / 排行 / 书架同步 / 章节预取 / 离线缓存 | 接近漫画源的完整体验 | 5–8 人日 |

建议先做 A，观察一版再加 B。

## 2. 站点结构（实测）

| 用途 | URL | 说明 |
| --- | --- | --- |
| 搜索 | `/search.html?q={kw}&f=_all` | `f` 取 `_all` / `title` / `author` / `tag`；分页 `&p={n}`；排序 `&sort=relevance` |
| 分类 | `/lists/{catId}.html?page={n}` | 每页 50 本；分类号见首页导航（62=玄幻、64=都市…），2 位数字 |
| 分类排序 | `/all/id/{catId}/order/word+desc.html`、`.../hits+desc.html` | 字数 / 人气；默认按更新 |
| 榜单 | `/other/rank_hits/order/hits_day.html` | 日 / 周 / 月 / 总：`hits_day` / `hits_week` / `hits_month` / `hits`；**必须带 Referer，否则 404** |
| 详情 | `/novel/{novelId}.html` | 书页，只有"最新章节"5 条 |
| 全目录 | `/other/chapters/id/{novelId}.html` | **一次返回全部章节**，无分页（实测 1849 章在一个页面内，195 KB） |
| 正文 | `/book/{bookId}/{chapterKey}.html` | 章节路径里的 `bookId` ≠ `novelId`，必须从目录页/详情页链接里取 |

要点：

- 搜索无结果时页面仍 200，靠 `.errortips`（文案含"找不到"）判定，不能只看状态码。
- 章节页无章内分页（不存在"下一页"续页），一章一页拿全。
- 章节列表按正序（序章 → 第 N 章），可直接当目录顺序。
- 榜单页对 Referer 敏感：裸请求 404，带 `Referer: https://www.alicesw.com/` 才 200。抓取端必须统一带上。
- 分类 / 榜单是同一套表格行（`div.rec_rullist ul`），一个解析器覆盖两处。

## 3. 选择器（已实测匹配到节点）

**搜索结果** `div.list-group-item`（每页 10 条）

| 字段 | 选择器 |
| --- | --- |
| 书名 / 链接 | `h5 > a`（`href=/novel/{id}.html`；标题内含 `<em>` 高亮，需 `TextContent` 后去空白） |
| 状态 | `h5 > small.text-muted`（`[已完结]`） |
| 作者 | `p` 内 `作者：` 后的 `a` |
| 字数 / 浏览 | 同一 `p` 的文本节点（`字数：12.12万`、`浏览：87509`） |
| 简介 | `p.content-txt` |
| 标签 | `p.text-muted` 内 `a`（`f=tag`） |
| 时间 | `p.timedesc` |

**详情页**

| 字段 | 选择器 |
| --- | --- |
| 书名 | `.novel_title` |
| 信息行 | `.novel_info p`（作者 / 分类 / 热度·收藏 / 字数·章节 / 状态 / 最新） |
| 封面 | `img.lazyload_book_cover` 的 `data-src`（CDN `img.321cdn.com`，`onerror` 回落到占位图） |
| 简介 | `div.jianjie p`（注意 `div.box_intro` 是空的，别抓错） |
| 标签 | `.tags_list a` |

**目录页**：`ul.mulu_list li a` → `href=/book/{bookId}/{chapterKey}.html`，`TextContent` 即章节名。

**正文页**：`div.read-content.j_readContent` 下的 `<p>` 段落（实测 120 段，共 6.9k 字，段落内无广告注入、无 URL 残留）；字数 `span.j_chapterWordCut`；更新时间 `.j_updateTime`；上一/下一章靠锚文本"上一章""下一章"定位（`.prev` / `.next` 是阅读器字号控件，不是章节导航，别混）。

**分类 / 榜单页**：`div.rec_rullist ul` 一行一本书 —— `li.one` 序号、`li.sev a` 分类（`/lists/{id}.html`）、`li.two a` 书名（`/novel/{id}.html`）、`li.three a` 最新章节、`li.four` 作者、`li.five` 字数（"58.13万"）、`li.six` 更新时间、`li.diyhot` 人气。分页链接是 `?page=N`。

**分类列表**：首页 `a[href^='/lists/']` 里**两位数字 id** 的才是分类；书页也会用 `/lists/{bookId}` 表示"本书分类"（五位数字），必须排除。

## 4. 反爬与稳定性评估

| 项 | 实测结果 |
| --- | --- |
| TLS | 证书校验通过（OpenSSL 严格校验 OK），无自签、无 MITM 要求 |
| WAF / Cloudflare | 无。响应头只有 `nginx`，无 `cf-ray`、无 `__cf_bm` |
| JS 挑战 | 无。正文就在首包 HTML 里，不用执行 JS |
| 登录态 | 不需要。搜索 / 详情 / 目录 / 正文全部匿名可取 |
| 限流 | 连续 15 次章节请求全部 200，无 429 / 无验证码（单次 1.3–4.7 s 为本地代理延迟，非站点限制） |
| robots.txt | 仅禁 `MJ12bot` 与 `/jump/age_gate.html`，其余允许 |
| 地域限制 | `prohibit/geo-block.js` 只在**浏览器端**读 `api.ip.sb`，且只拦美国犹他州 IP；服务端不拦，对国内用户无影响 |
| 正文加密 | 无。纯 UTF-8 HTML（已核对 CJK 占比 0.94，非图片化、非字体混淆） |

结论：不需要 `CurlImpersonateClient` 那套指纹伪装，也不需要 `MultiTierFetcher` 的多级降级，普通 `HttpClient` + `AngleSharp` 就够。

## 5. 与现有架构的差距

1. **没有"小说源"抽象**。`ResourceKind.Novel` 已存在（顶栏"本地小说"胶囊、`NovelNavSectionProvider`、`NovelAccentBrush` 都在），但 `Core/Sources` 里只有 `IComicSource` / `IVideoSource` / `IShortDramaSource`，小说侧是空的。
2. **`SourceManager` 只装漫画源**：`IReadOnlyList<IComicSource>`，`Current` 语义是"当前漫画源"，直接塞小说源会污染漫画的聚合搜索 / 分类 / 排行。
3. **阅读器只认文件路径**：`NovelReaderView.LoadFile(path)` 里 `File.ReadAllBytesAsync` + 编码探测 + 分页，在线章节文本没有入口。
4. **阅读进度按路径键控**：`NovelReadingHistoryService.Normalize(fullPath)` 把 key 转小写并反斜杠化，在线进度需要单独的 key 空间（如 `online:alicesw:{bookId}:{chapterKey}`），否则和本地文件路径混在一起。
5. **没有正文清洗层**：漫画源是"取图片 URL"，小说源需要"取文本 + 清洗"（去首尾空白、去重复空行、把 `&nbsp;`、`　` 全角缩进统一）。

## 6. 集成方案

### 6.1 接口草案（Core）

```csharp
public interface INovelSource
{
    ComicSourceInfo Info { get; }                                   // Kind = ResourceKind.Novel
    Task<NovelSearchPage> SearchAsync(string keyword, int page, NovelSearchField field = NovelSearchField.All, CancellationToken ct = default);
    Task<NovelDetail> GetDetailAsync(string novelId, CancellationToken ct = default);
    Task<IReadOnlyList<NovelChapter>> GetChaptersAsync(string novelId, CancellationToken ct = default);
    Task<string> GetChapterTextAsync(NovelChapter chapter, CancellationToken ct = default);  // 已清洗的纯文本
}
```

配套模型：`NovelSummary`（Id/Title/Author/CoverUrl/Status/WordCount/Tags/UpdatedAt）、`NovelChapter`（BookId/Key/Title/Url/Order）、`NovelDetail`（Summary + 简介 + 章节数）。

### 6.2 方案 A：单章在线阅读

- Core 新增 `Sources/Alicesw/`：`AliceswConstants`（域名池）、`AliceswHttpClient`（UA + Referer + 重试）、`AliceswParser`（第 3 节的选择器）、`AliceswSource`。
- App 新增 `Services/NovelSourceManager`（与 `SourceManager` 同构，装 `INovelSource`），避免污染漫画源。
- App 新增 `Views/NovelOnlineView`（沿用 `CardGridViewBase` + `VirtualizedCardGrid`，卡片走 `MediaCardAdapters`），路由 `novel.online`，导航项加到 `NovelNavSectionProvider`。
- 章节列表页复用现有列表控件；点章节 → 取正文 → `NovelReaderView.LoadText(title, text, historyKey)`（新增重载，内部跳过解码、直接走 `SplitChunks` / `RenderPage`）。
- 进度：`NovelReadingHistoryService` 增加按 `historyKey` 写入的能力（现成的 `Save` 已接受任意字符串路径，只需约定 key 前缀即可，无需改存储）。

### 6.3 方案 B：整本导出为 txt（推荐叠加）

把「目录 + 各章正文」按 `第N章 标题\n\n正文\n\n` 拼成单文件，落到用户指定的目录（默认 `config\小说导出\{书名}.txt`），然后走现有本地小说链路（索引 / 书架 / 阅读器 / 进度全免费）。

好处：一次导出永久离线可读、可进本地库、进度与排版行为与本地书完全一致；坏处：全书抓取耗时（1849 章 × ~2 s ≈ 1 小时量级），需要断点续传与并发上限。

建议并发 2–3、章间 200–500 ms 间隔，失败章节记入 `*.missing.json` 供重试。

## 7. 风险与注意

1. **域名轮换**：站点有 `.com` / `.tw` 两个入口 + `asw5.cc` 发布页，历史上换过域名。建议直接复用 `ApiDomainPool` 的模式（配置 `novelDomains` + 失败冷却），别写死一个域名。
2. **站点合规性**：内容为成人向。当前实现不做年龄弹窗，靠「设置 → 小说 → 在线书库」的开关（默认开）控制整组入口，关掉后左栏不显示「在线书库 / 分类 / 排行」。
3. **礼貌抓取**：站点无 `Crawl-delay` 声明，也没有明显限流，但仍应限制并发（≤3）与频率（≥200 ms 间隔），避免给站点造成压力，也避免 IP 被临时封禁。
4. **内容版权**：仅作个人阅读缓存，导出文件不要回传或再分发；仓库 `README` 的免责声明已覆盖此类用途，建议在源设置页再写一句。
5. **正文清洗**：不同书可能夹带站点推广行（本次抽样的书正文是干净的，但不能假设所有书都干净）。建议清洗规则：去空段、去含 `http://` / `www.` / 站名关键词的段落、去重复段落（相邻 3 段哈希去重）。
6. **章节数上限**：单页 1849 章的目录响应约 195 KB，`AngleSharp` 解析正常；若遇到更大目录（万章级），需评估 5–10 MB 级 DOM 的内存占用，必要时改用正则流式提取链接。
7. **未验证项（实现前建议补测）**：
   - 已下架 / 需权限的章节页返回什么（是否存在"章节不存在"软 404）
   - 超长章节（>2 万字）是否仍单页返回
   - 站点对 `Accept-Encoding: br` 的处理（`HttpClient` 默认 gzip/deflate/br 应无碍）
   - 繁体站在同结构下是否完全一致（若做双站切换需比对一遍选择器）
8. **本次评估的环境限制**：DSH 沙箱内 .NET 的 Schannel 取不到凭证（`SEC_E_NO_CREDENTIALS`），`HttpClient` 连 `example.com` 也失败；因此"用 .NET 实际抓取"这一步未能在沙箱内跑通，站点结构结论来自 OpenSSL 路径的抓取。**这是沙箱问题，不是站点问题**（同一台机器上 Python 严格校验模式访问该站 200）。应用自身以普通用户进程运行，不受此限。
