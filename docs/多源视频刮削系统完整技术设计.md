# 多源视频刮削系统完整技术设计

## 1. 背景与目标

当前项目的视频刮削由 `VideoScrapeService` 编排，已经包含 JavBus、JavDB、AirAv 三个来源，以及一个初步的 `VideoMetadataAggregator`。现有实现可以完成基础的并发抓取与字段合并，但与参考项目 [Amane](https://github.com/sqzw-x/amane) 相比，还缺少完整的任务化调度、字段级抓取图、站点快照缓存、来源追踪、插件式扩展和多语言节点能力。

本文档定义一个面向本项目的完整多源刮削系统设计方案，目标是让视频刮削具备以下能力：

1. 来源可插拔：新增站点时不需要修改主流程。
2. 字段级择优：标题、简介、封面、评分等字段可以来自不同站点。
3. 失败隔离：任一来源失败不影响其他来源。
4. 来源可追踪：每个最终字段都能知道来自哪个来源。
5. 站点快照缓存：重刮时可复用旧数据，只补抓缺失来源。
6. 任务化执行：支持队列、重试、取消、优先级和后续任务。
7. 资源去重存储：封面、剧照等资源按 URL 或内容哈希复用。
8. 可观测性：UI 可以展示每个站点的成功、失败、拦截、超时和缓存命中状态。

参考项目是 Amane，但本方案不直接复制其代码，而是根据本项目现有的 C# / WPF / 本地库结构重新设计。

## 2. 总体架构

```text
文件扫描 / 手动触发 / 定时任务
        ↓
番号解析器 VideoNumberParser
        ↓
内容类型路由 Router
        ↓
视频刮削任务队列 ScrapeTaskQueue
        ↓
VideoScrapePipeline
        ├── Source Registry
        ├── Cache Layer
        ├── Fetch Graph Scheduler
        └── Field Merger
        ↓
VideoScrapeAggregate
        ├── 合并后的元数据
        ├── FieldSources
        ├── SourceAttempts
        └── SourceSnapshots
        ↓
资源下载 ResourceStore
        ↓
本地库更新 / NFO 写入 / UI 刷新
```

核心原则：

| 原则 | 说明 |
| --- | --- |
| 站点适配器只负责单站解析 | JavBus 不关心 JavDB，AirAv 不负责合并 |
| Pipeline 只负责编排 | 路由、调度、缓存、合并、追踪都在 Pipeline 内完成 |
| 合并规则显式配置 | 不再在服务代码中硬编码“JavDB 补充”“AirAv 补中文” |
| 每个来源独立容错 | 单站网络错误不会导致整个番号失败 |
| 所有最终字段可溯源 | 每个字段记录来源 ID |
| 快照先于最终结果 | 先保存各站点解析结果，再生成聚合结果 |

## 4. 领域模型

### 4.1 内容类型

与 Amane 对齐，使用七种内容分类。当前项目已有 `VideoNumberKind`，建议扩展为更完整的 `VideoContentKind`：

```csharp
public enum VideoContentKind
{

    Censored,
    Fc2,
    Uncensored,
```

兼容策略：

* 继续保留 `VideoNumberKind`，用于现有调用方；
* 在 Pipeline 边界转换成 `VideoContentKind`；
* 新逻辑只依赖 `VideoContentKind`。

### 4.4 站点快照

每个来源的解析结果单独保存，而不是只保存最终合并结果：

```csharp
public sealed class VideoSourceSnapshot
{
    public required string Number { get; init; }

    public required string SourceId { get; init; }

    public string? Language { get; init; }

    public required string SchemaVersion { get; init; }

    public required VideoScrapeMetadata Metadata { get; init; }

    public Dictionary<string, object?> RawExtras { get; set; } = new();

    public DateTimeOffset FetchedAt { get; init; } = DateTimeOffset.UtcNow;
}
```

说明：

* `Metadata` 是规范化后的数据；
* `RawExtras` 只保存少量必要的原始信息，不建议保存整页 HTML；
* `SchemaVersion` 用于解析器升级后失效旧缓存；
* `Number + SourceId + Language` 构成缓存主键。

### 6.3 路由校验规则

Pipeline 启动或配置保存时应检查：

1. 来源 ID 必须存在或为已注册插件。
2. 来源必须声明支持该内容类型。
3. 字段优先级中的来源必须在内容路由内。
4. 路由不允许重复来源。
5. 禁用的来源不参与执行，但不应破坏已有配置。
6. 未识别的来源可以记录警告，但不阻断启动。

## 7. 抓取图与调度器

这是整个系统的核心。

### 7.1 抓取节点

一个抓取节点不是简单的一个网站，而是：

```text
(sourceId, language)
```

例如：

```text
(javbus, null)
(javdb, null)
(airav, zh-CN)
(dmm, ja-JP)
```

大多数站点只需要默认语言：

```text
(javbus)
(javdb)
(airav)
```

未来如果某个来源支持多语言，则展开为多个节点。

### 7.2 字段链

每个字段都有一条来源链：

```text
title:
  airav -> javdb -> javbus

description:
  airav -> javdb

coverUrl:
  javbus -> javdb

score:
  javdb

previewImageUrls:
  javbus -> javdb
```

如果高优先级来源没有返回有效值，就沿链向后回退。

### 7.3 波次调度伪代码

```csharp
var graph = VideoFetchGraphBuilder.Build(fieldPriorities, routeNodes);

while (!graph.IsComplete)
{
    var nodes = graph.GetRunnableNodes();

    var tasks = nodes.Select(node =>
        ExecuteNodeAsync(node, request, cache, cancellationToken));

    var results = await Task.WhenAll(tasks);

    graph.Apply(results);
    merger.Apply(results);
}

return merger.BuildFinalResult();
```

### 7.4 调度策略

| 字段类型 | 策略 |
| --- | --- |
| 必需标量字段，例如 title | 找到非空值后停止沿链继续 |
| 可选标量字段，例如 director | 找到第一个非空值即可；若来源成功但值为空，也接受空值 |
| 集合字段，例如 actors、tags | 尽量收集所有已执行节点的结果 |
| 收集型字段，例如 score、external id | 按来源分别保留 |
| URL 类字段 | 通常从多个来源收集，但需要去重 |

### 7.5 第一阶段简化实现

考虑到当前只有三个来源，第一阶段不必实现完整 DAG 引擎，可以先实现：

```text
1. 解析有效路由
2. 并发调用所有可用来源
3. 等待全部完成
4. 按字段优先级合并
```

第二阶段再引入真正的 `VideoFetchGraphScheduler`，以减少不必要的站点请求。

## 8. 合并规则

### 8.1 标量字段

选择顺序：

```text
fieldPriorities[field]
    → contentRoutes[contentKind]
        → source registry 中实际可用来源
```

示例：

```text
title priority:
airav -> javdb -> javbus

如果 airav 成功但标题为空：
使用 javdb

如果 javdb 成功且标题非空：
title.source = javdb
```

### 8.2 集合字段

集合字段做并集：

```text
actors:
javbus: ["A", "B"]
javdb:  ["B", "C"]

result:
["A", "B", "C"]
```

去重规则建议：

1. 忽略大小写；
2. trim 空白；
3. 保留首次出现顺序；
4. 记录贡献来源。

### 8.3 标题特殊处理

标题不能简单当作普通标量处理。

推荐规则：

1. 如果配置希望中文标题：
   * 优先选择不含假名的标题；
   * 如果选中中文标题，同时找到日文标题，则日文标题写入 `OriginalTitle`。
2. 如果没有中文标题：
   * 使用日文或其他来源标题；
   * 不做机器翻译，除非启用了翻译服务。
3. `OriginalTitle` 优先来自明确的原题字段，例如 JavDB 的 `origin-title`。

### 8.4 评分

不要直接把不同站点的评分平均。

推荐结构：

```json
{
  "scores": {
    "javdb": 8.2,
    "dmm": 4.5,
    "r18dev": 85
  },
  "primaryScoreSource": "javdb"
}
```

如果现有 `VideoItem.Score` 只能保存一个数值，则保留主评分字段，同时在扩展表中保存全部来源评分。

### 8.5 布尔字段

布尔标记采用 OR：

```text
hasMagnet       = javbus || javdb || airav
hasChineseSubtitle = javdb || airav || iqqtv
```

### 8.6 字段溯源

每次成功赋值都要写入：

```json
{
  "title": "airav",
  "description": "airav",
  "coverUrl": "javbus",
  "score": "javdb",
  "actors": "javbus+javdb"
}
```

集合字段可以有多个贡献来源。

## 9. 缓存设计

### 9.1 缓存层级

```text
Memory Cache
   ↓
Disk Snapshot Cache
   ↓
Network Source
```

第一版可以直接落盘 JSON；数据量大后迁移到 SQLite。

### 9.2 缓存目录

```text
config/video-source-cache/
  ssis-405/
    javbus.json
    javdb.json
    airav.json
```

文件名必须规范化：

```text
number.ToLowerInvariant()
```

### 9.3 缓存文件结构

```json
{
  "schemaVersion": "v1",
  "number": "SSIS-405",
  "sourceId": "javdb",
  "fetchedAt": "2026-08-26T12:00:00Z",
  "metadata": {
    "title": "...",
    "score": 8.2
  },
  "rawExtras": {}
}
```

### 9.4 缓存模式

| 模式 | 行为 |
| --- | --- |
| Auto | 有缓存读缓存，缺失来源联网补抓 |
| RefreshMissing | 只抓取路由中缺少缓存的来源 |
| ForceRefreshAll | 忽略缓存，全部重新联网 |
| CacheOnly | 只读缓存，不发网络请求 |
| BypassExpired | 过期缓存仍可用于兜底，但后台刷新 |

### 9.5 失效条件

满足任一条件时认为缓存不可直接使用：

1. `schemaVersion` 不匹配；
2. 用户手动强制刷新；
3. 缓存超过 TTL；
4. 来源基础地址或解析器版本变化；
5. 上一次结果是 `Blocked` 或 `HttpError`，且未达到最小重试间隔。

## 11. HTTP 层

### 11.1 共享客户端

所有视频刮削来源应共享同一个 HTTP 工厂，避免每个站点各自维护一套代理、超时、限速逻辑。

```csharp

{
    HttpClient Create(string sourceId);
}
```

### 11.2 限速

按 host 限速，而不是按 source 限速：

```text
www.javbus.com -> 1 req/s
javdb.com      -> 0.5 req/s
airav.io       -> 0.5 req/s
```

实现建议：

```csharp
public sealed class HostRateLimiter
{
    private readonly ConcurrentDictionary<string, SemaphoreSlim> _semaphores = new();
    private readonly ConcurrentDictionary<string, DateTime> _nextAllowedAt = new();
}
```

### 11.3 重试策略

默认只重试这些情况：

| 类型 | 是否重试 |
| --- | --- |
| 网络连接失败 | 是 |
| 超时 | 是 |
| HTTP 408 | 是 |
| HTTP 429 | 是 |
| HTTP 503 | 是 |
| HTTP 504 | 是 |
| HTTP 403 | 谨慎重试或切换 curl 兜底 |
| Cloudflare challenge | 不立即重试 |
| 页面结构变化导致解析失败 | 否 |

### 11.4 反拦截策略

第一阶段保持现有方式：

1. 浏览器 User-Agent；
2. Accept-Language；
3. Referer；
4. Cookie；
5. 可选代理；
6. AirAv 使用系统 curl 兜底。

后续可选增强：

1. 独立 curl impersonation 进程；
2. 无头浏览器渲染；
3. 每个 host 独立 cookie jar；
4. 请求录制与回放调试。

## 21. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 站点页面结构变化 | 解析失败 | fixture 测试 + schema version + 来源隔离 |
| Cloudflare / WAF | 来源不可用 | curl fallback、代理、浏览器渲染预留 |
| 多源数据冲突 | 元数据不一致 | 显式字段优先级 + 冲突日志 |
| 缓存过大 | 磁盘占用 | TTL + 清理任务 + 只存规范化快照 |
| 并发过高 | 被封禁 | 全局并发 + 每 host 限速 |
| 用户旧配置不兼容 | 启动失败 | 默认值补全 + 安全校验 |
| UI 阻塞 | 体验差 | 后台任务队列 + cancellation token |
| 来源质量差异大 | 错误字段覆盖高质量字段 | 字段级优先级 + 来源追踪 |

## 22. 最终验收标准

系统完成后应满足以下标准：

1. 新增一个视频来源，只需实现 `IVideoScrapeSource` 并注册，不需要修改 `VideoScrapePipeline`。
2. 任一来源失败，任务仍能基于其他来源产出结果。
3. 每个最终字段都可以回答“它来自哪里”。
4. 重刮同一番号时，默认能复用来源快照。
5. 新增来源后重刮，只抓取新来源，不重复抓取已有来源。
6. 强制刷新会忽略缓存并重新抓取全部有效来源。
7. 用户可以为标题、简介、封面、评分、剧照等字段配置优先来源。
8. UI 能显示每个来源的成功、失败、超时、拦截和缓存命中状态。
9. 图片按 URL 或内容哈希去重，避免重复下载。
10. 任务可以被取消、重试，并且不会阻塞 WPF UI。
11. 全部 23 个影片来源和 4 个演员来源均已实现或明确标注为禁用/预留状态。
12. 七种内容类型（censored / uncensored / chinese / amateur / western / fc2 / hentai）均有可用路由。
13. 多语言站点（iqqtv / r18dev）正确展开为 (source, language) 节点。
