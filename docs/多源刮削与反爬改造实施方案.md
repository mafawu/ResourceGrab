## 1. 任务目标与总览

本仓库（ResourceGrab）是一个 .NET 10 / WPF 桌面应用：多源漫画/视频下载器 + 本地媒体库。视频模块的**元数据刮削**当前只靠 3 个老刮削源（JavBus / JavDb / AirAV）。设计文档《多源视频刮削系统完整技术设计.md》（docs/ 目录）规划了 **23 个影片刮削源 + 4 个演员专用源**，其中 20 个影片源在代码里只有**空壳占位**（见 3.2 节）。

本次改造四件事，**必须按顺序执行**：

| 阶段 | 内容 | 依赖 |
|---|---|---|
| **阶段 0** | 反爬底座：多级抓取客户端栈（TLS 指纹）、拦截页识别、Cookie 持久化、per-source 配置、修已知 bug | 无 |
| **阶段 1** | 新管道通电：DI 注册、新建图调度编排器、执行器切换、引擎开关 | 阶段 0 |
| **阶段 2** | 实现 20 个刮削源（分批） | 阶段 1（批 A 可与阶段 0 并行） |
| **阶段 3** | 观测：per-source 成功率 / Block 率统计展示 | 阶段 1 |

关键判断依据（2026-08-30 实测）：站点 Cloudflare 防护会 403 掉裸 .NET HttpClient 与系统 curl（"Just a moment" 挑战页），**先做反爬底座，否则阶段 2 实现的源全部白做**。

## 3. 参考项目 amane（设计蓝本，怎么用）

`https://github.com/sqzw-x/amane`（Python 项目，GPL-3.0）是本仓库新管道设计文档的蓝本。**如果你有外网**，逐源实现时先读它的对应文件再写 C#；**如果没有外网**，按第 7 章对照表里已提炼的要点 + 自己对站点的知识实现，并可在运行期对站点做实测探查。

### 3.1 amane 的架构（crawlers/ 目录）

- `crawlers/base.py`：`Crawler(ABC)` 模板方法基类。子类只需实现类方法 `profile()`（返回 `CrawlerProfile`：name、base_url、urls、默认 cookies/headers、capabilities、multi_language）与两个抽象方法 `_search(query, options)`（番号→详情页 URL，未命中返回 None）、`_scrape(url, options)`（URL→元数据 dict，失败 None）。公开入口 `fetch()` 串起 search→scrape 并统一日志计时。**这个三件套结构正是 `IVideoScrapeSource` 的原型。**
- `crawlers/registry.py`：`dict[站点名 → 爬虫类]` 显式注册表，`register()` 可当装饰器，`get(site)` 未注册返回 None。
- `crawlers/factory.py`：`CrawlerFactory` 单例 HttpClient 注入 + 按名称缓存实例 + 用户 SiteConfig 覆盖 base_url/cookies。
- `crawlers/http.py`：`HttpClient` 薄封装，双客户端 —— **`WebClient` 基于 curl_cffi（模拟浏览器 TLS 指纹，过 Cloudflare 被动检测的关键）**，`BrowserClient` 基于 patchright（Playwright 反检测分支，无头渲染解 JS 挑战）；`classify_block(text)` 启发式识别拦截页抛 `SourceError`。这是阶段 0 要在 .NET 侧重建的能力。
- `crawlers/sites/*.py`：23 个站点模块（**全部是真实现**，最小的 2.2KB、最大的 dmm.py 24.5KB）+ `dmm_api.py`（DMM GraphQL payload 构造）。
- `crawlers/actor/sites/`：4 个演员源（gfriends / javdb / minnano / wikipedia）。
- `crawlers/r18dev/`：R18.dev 离线 PostgreSQL 镜像导入器（database/importer/mapper/models/repository）。

### 4.1 拦截页识别 BlockDetector

把 `MissAvSource.cs` 里**从未被调用的私有方法 `IsCloudflareBlock`**（约 295 行，死代码）提升为公共组件并扩展：

```csharp
public static class BlockDetector
{
    /// <summary>综合状态码与 body 判定是否被反爬拦截。</summary>
    public static bool IsBlocked(HttpStatusCode? status, string? body)
    {
        if (status is HttpStatusCode.Forbidden
                     or HttpStatusCode.ServiceUnavailable
                     or (HttpStatusCode)429) return true;
        if (string.IsNullOrEmpty(body) || body.Length < 100) return false;
        var head = body.AsSpan(0, Math.Min(body.Length, 3000));
        return head.Contains("just a moment", StringComparison.OrdinalIgnoreCase)
            || head.Contains("cf-browser-verification", StringComparison.OrdinalIgnoreCase)
            || head.Contains("cf_chl_", StringComparison.OrdinalIgnoreCase)
            || head.Contains("attention required", StringComparison.OrdinalIgnoreCase);
    }
}
```

**所有源拿到 HTML 后先过 `BlockDetector`**：命中 → 返回 `VideoSourceFetchResult.Failure(Id, VideoSourceOutcome.Blocked, "cloudflare-challenge")`，让上层降级/换镜像，而不是把挑战页当搜索结果解析出 0 条。

### 4.2 多级抓取客户端栈 MultiTierFetcher

统一入口，替代散落在各源的裸 HttpClient 调用：

```csharp
public enum FetchTier { HttpClient = 0, CurlImpersonate = 1, FlareSolverr = 2 }

public sealed record FetchOptions(
    string? Referer = null,
    IReadOnlyDictionary<string, string>? ExtraHeaders = null,
    int MaxTier = 2);          // 默认允许降级到 L2

public sealed record FetchResult(int StatusCode, string Body, FetchTier Tier);

public interface IResilientFetcher
{
    /// <summary>按 L1→L2(→L3) 顺序尝试；每级先查 CookieJar，响应后回写；最终失败抛 HttpRequestException。</summary>
    Task<FetchResult> GetAsync(string url, FetchOptions? options, CancellationToken ct);
}
```

`MultiTierFetcher` 实现（建议构造参数：`HttpClient l1Client, CurlImpersonateClient? l2, DomainCookieJar cookieJar, ILogger?`）：

1. 从 `cookieJar.GetCookieHeader(uri)` 取 Cookie 附到请求；L1 发送（UA/Accept-Language/自动解压/代理由 L1 HttpClient 携带）。
2. 响应 `Set-Cookie` 回写 cookieJar；若 `BlockDetector.IsBlocked` 且存在下一级 → 降级重试同一 URL。
3. L2 = `CurlImpersonateClient`（4.3）；仍失败/仍 Blocked → 抛出（源翻译为 `Blocked`/`HttpError`）。
4. 请求间按源限速：保留老 `VideoScrapeHttpClient` 的 per-host `_nextRequestByHost` 思路（按域名排下一次允许请求时间，`RateLimitPerSecond` 来自 `VideoSourceConfig`）。**并发节流放在 Fetcher 层按 sourceId 隔离**（每个 sourceId 一个 SemaphoreSlim，上限取全局 `VideoScrapeSettings.Concurrency`）。

### 4.3 curl-impersonate 集成（TLS 指纹层，本方案核心）

.NET 没有 curl_cffi 等价物，采用子进程方案：**curl-impersonate 的 Windows 构建**（社区维护的 `curl-impersonate-win` 等发布，提供 `curl_chromeNNN` 系列可执行文件，TLS 指纹模拟 Chrome）。

实现要点：

```csharp
public sealed class CurlImpersonateClient
{
    // exe 探测顺序：AppPaths.AppDataDir/curl-impersonate/ → 应用目录 assets/curl-impersonate/
    // 探测不到 → Available=false，MultiTierFetcher 跳过 L2（应用必须能在无 L2 时正常工作）
    public bool Available { get; }

    public async Task<FetchResult> GetAsync(string url, string? cookieHeader,
        IReadOnlyDictionary<string, string>? extraHeaders, CancellationToken ct)
    {
        // Process 调用，参数一律 ArgumentList 逐个添加（参考 MissAvSource.GetWithCurlAsync 的写法）：
        //   -sS -L --compressed --max-time {timeout}
        //   -H "Cookie: ..."（来自 cookieJar）
        //   -H "Referer: ..."（如有）
        //   不传 -A：impersonate 构建自带浏览器 UA 与 TLS 指纹，手动 -A 反而使 JA3 与 UA 不匹配
    }
}
```

**分发方式**：不自动下载（避免供应链风险），由用户按 README 说明自行下载 curl-impersonate 的 Windows 构建并放入指定目录；应用启动时探测，`Available=false` 时整个 L2 层透明跳过。

### 4.4 Cookie 持久化 DomainCookieJar

```csharp
public sealed class DomainCookieJar
{
    // 内存 Dictionary<string domain, List<(name, value, boundUa, fetchedAt)>>，
    // 构造时从 {AppDataDir}/video-cookies.json 加载，变更后 1.5s 去抖落盘（参考 VideoLibraryService 的去抖模式）
```

### 6.1 通用实现模板

每个源一个文件（已建好空壳，直接填充）。以 XcitySource 为例的标准骨架：

```csharp
public sealed class XcitySource : IVideoScrapeSource
{
    private readonly IResilientFetcher _fetcher;   // 阶段 0 产物；没做完阶段 0 前可临时注入 HttpClient
    private readonly ILogger? _logger;

    public string Id => "xcity";
    public string DisplayName => "XCity";
    public IReadOnlySet<VideoContentKind> SupportedKinds { get; } =
        new HashSet<VideoContentKind>([VideoContentKind.Censored]);

    public async ValueTask<VideoSourceFetchResult> FetchAsync(VideoSourceRequest request, CancellationToken ct)
    {
        var sw = System.Diagnostics.Stopwatch.StartNew();
        try
        {
            // 1) 番号规范化：全大写、统一分隔符；需要的源做零填充变体（见 6.4 DMM）
            // 2) 搜索：GET 搜索页 → AngleSharp 解析结果列表 → 精确匹配番号 → 得详情页 URL；没命中 → NoMatch
            // 3) 详情：GET 详情页（带 Referer）→ BlockDetector 判定（先于解析！）→ 解析字段
            // 4) 构造 VideoScrapeMetadata（字段名对齐 2.4 节；页面没有的字段留默认值，不要造假数据）
            // 5) SourceUrls["xcity"] = 详情页 URL（Merger 会聚合）
            return VideoSourceFetchResult.Success(Id, metadata, (int)sw.ElapsedMilliseconds, request.Language);
        }
        catch (OperationCanceledException) { ... return Cancelled; }
        catch (HttpRequestException ex)    { ... return Failure(Id, HttpError/Blocked, ex.Message); }
        catch (FormatException ex)         { ... return ParseError; }
    }
}
```

硬性要求：

- **所有 HTML 解析用 AngleSharp**（`HtmlParser` + `QuerySelector`/XPath），禁止字符串切割主逻辑。参考 `MissAvSource.ParseSearchCards` 与老 `JavBusScraper` 的风格。
- 每个请求带站点合理 `Referer`；需要年龄确认的站（DMM/Getchu/XCity/MGStage 等）用 profile cookie（如 DMM `age_check_done=1`），cookie 值写进 `GetDefaultSourceConfigs()` 对应条目的 `Cookie` 或源内常量。
- 搜索匹配要**精确校验番号**：正则要求前缀前无字母、数字后无数字（防 `SNOS-1` 匹上 `SNOS-123`），老 `JavBusScraper` 与 amane 均如此。
- 单源失败绝不抛出异常穿透：`FetchAsync` 内 catch 全部，翻译为对应 Outcome（契约见 2.3 节表）。
- 实现完成后：`GetDefaultSourceConfigs()` 中该源 `Enabled = true`，并在 DI 注册（5.1 注释处）。

## 9. 已知坑（踩过的，务必避开）

1. **`Sources/*.cs` 20 个空壳**全部返回 `Disabled/"Not yet implemented"`——不要误以为部分实现了。
2. **`MissAvSource.GetWithCurlAsync` 不传代理**：需要代理的网络下兜底必失败（4.6 #1）。
3. **`MissAvSource.IsCloudflareBlock` 是死代码**（无调用点）；`IVideoSource.RequiresCookieWarmup/RequiresCurlFallback` 同样无消费方。
4. **`MirrorUrls` 含重复域名**（missav.ws 与 BaseUrl 重复）且缺实测可用的 missav.live——镜像轮换第一次重试是浪费的。
5. **`IsSourceEnabled` 对"无配置条目"的源返回 false**（`SourceConfigs` 是白名单式字典，TryGetValue 失败即 false）。新源实现后必须显式在 `GetDefaultSourceConfigs()` 加 `Enabled=true` 条目；仅 DI 注册不启用是常见漏项。
6. **`VideoFetchGraphScheduler` 无全局并发上限**——并发控制依赖每源限速器。**2026-08-30 起已改为分级波次调度**：节点带 `Tier`（1=快且稳：missav/javbus/javdb；2=中等；3=慢或地理受限），先抓 Tier 最小的首批（2-3 个源），任一源命中即停，全部未命中才继续下一波（缓存命中视为已命中）。Tier 取自 `sourceConfigs.<id>.tier`（默认 2）。若仍发现瞬时并发过高，在各源限速器上加 `SemaphoreSlim` 而不是调度器全局闸。
7. **测试项目不在 slnx**，改完 Core 记得单独 `dotnet test`，否则感知不到测试编译错误。
8. **配置兼容**：`config.json` 是用户既有数据，所有新增配置字段必须有默认值且可选（JsonPropertyName 序列化容忍缺失）；`ConfigService.cs` 有逐字段拷贝逻辑（126 行附近），新增 `VideoScrapeSettings`/`VideoSourceConfig` 字段后检查该处是否需要同步。
9. **许可证**：amane 为 GPL-3.0，移植解析逻辑时重写实现（参考事实，不翻译代码，见 3.2）。
10. **`ContentRoutes`/`FieldPriorities` 的默认值**（`VideoScrapeConfigExtensions.cs:96-117`）引用了尚未实现的源 ID（dmm、official、avsox 等）——validator 会报 warning，属预期；通电后（阶段 1）这些 warning 不应阻塞运行，未注册源被 scheduler 自动跳过（`Failure(Disabled, "Source not registered")`）。
