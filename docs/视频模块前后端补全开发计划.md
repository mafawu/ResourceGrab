## 1. 总原则

1. **先接线、后新建**：已经写好的 UI（`VideoTaskDashboard`、`ScrapeReportPanel`）只差 DI 注册和调用方改写，先让它们活过来，性价比最高。
2. **新旧引擎并存、渐进切换**：新版 M1–M12 管道不直接推翻旧 `VideoScrapeService`，而是作为可切换的第二条路径接入，默认仍走旧引擎，验证稳定后再切默认。避免一次性大改引入回归。
3. **配置即契约**：`SettingsDialog` 里已经能编辑来源开关/内容路由/字段优先级，开发顺序要让这些旋钮真正驱动新引擎（否则是摆设）。
4. **消除孤儿代码**：`OnlineVideoView` 与主流程的 `VideoView.SearchPage` 是两套平行在线搜索实现，后者才是实际入口。统一到一处，避免后续维护两套。
5. **所有改动可灰度**：新功能通过配置开关控制是否启用，旧行为默认保留，出问题可回退。

## 2. 开发顺序与方案

### 阶段 0：让已建 UI 活过来（DI 接线，最高 ROI）

**目标**：用最小改动激活 `VideoTaskDashboard` 与 `ScrapeReportPanel`。
**范围**：仅 DI 注册 + 刮削调用方改写，不引入新功能。

**方案**：
- 在 [App.xaml.cs](F:\ProcessProject\C#\ResourceGrab\src\ResourceGrab.App\App.xaml.cs) 注册：
  - `services.AddSingleton<ScrapeReportService>();`（注意它当前是 `VideoScrapeService` 内部 `new` 出来的，需改为依赖注入，保证面板与引擎读的是同一实例/同一 `video-scrape-metadata.json`）。
  - `services.AddSingleton<VideoScrapeTaskQueue>(sp => new VideoScrapeTaskQueue(maxConcurrency, logger));`。
- 改写 `VideoScrapeService.ScrapeAsync`：在循环里用 `VideoScrapeTaskQueue.Enqueue(...)` 发布任务、更新进度，
  把现有 `VideoScrapeProgress` 回调桥接到队列的 `GetProgress()`/`TaskCompleted` 事件，
  使 `VideoTaskDashboard` 的定时刷新能拿到真实数据。
- `VideoScrapeService` 改为从 DI 取 `ScrapeReportService`（构造函数注入），删除内部 `new`。

**验收**：
- 启动刮削后，左侧"刮削任务"页能看到任务行、状态、来源尝试、取消/重试可用。
- 详情页底部"刮削报告"能展示字段溯源与来源执行记录。
- 不破坏现有进度条/日志行为。

### 阶段 1：新版刮削管道 M1–M12 真正接入运行链路

**目标**：让设计文档里的现代管道（多源合并、字段溯源、快照缓存、演员合并、插件）真正被消费，而不是死代码。
**范围**：DI 注册 + 配置消费 + 与旧引擎的切换。

**方案**：
1. **先核实配置持久化**：确认 `VideoScrapeSettings` 与 `VideoScrapeConfigExtensions`（`ContentRoutes`/`FieldPriorities`/`SourceConfigs`）的序列化链路是否打通。`SettingsDialog` 已调用 `PopulateSourceToggles`/`SaveContentRoutes`，需确认这些值是否落到 `config.json` 并可被新引擎读取；若未打通则先补齐（这是文档里 P0 提到的 `Advanced` 属性问题，需用真实代码验证，不要照抄文档假设）。
2. **注册新管道**到 [App.xaml.cs](F:\ProcessProject\C#\ResourceGrab\src\ResourceGrab.App\App.xaml.cs)：
   - `IVideoScrapeSourceRegistry` + `VideoScrapeSourceRegistry`
   - `VideoFetchGraphScheduler`、`VideoMetadataMerger`、`VideoActorMerger`
   - `IVideoSourceSnapshotCache`(DiskJsonSnapshotCache)、`IVideoResourceStore`(DiskVideoResourceStore)
   - `PluginLoader`（如启用插件）
3. **新增 `ScrapeAsync` 新版路径**：在 `VideoScrapeService` 内增加 `ScrapeWithPipelineAsync(...)`，
   通过 `VideoFetchGraphScheduler` 编排来源、`VideoMetadataMerger` 合并、`ScrapeReportService` 落盘溯源。
   保留旧 `ScrapeAsync` 作为默认。
4. **开关切换**：在 `VideoScrapeSettings` 增加 `UseNewPipeline` 开关；
   `VideoView.StartScrape` 按开关选择路径；默认 `false`，灰度验证后切 `true`。
5. **修正文档虚构项**：本阶段明确只接入"真实存在"的来源（Legacy JavBus/JavDB/AirAv + 新增的 `IVideoScrapeSource` 适配器），**不实现文档里虚构的 23 个源**；如未来要补源，按 `IVideoScrapeSource` 契约逐个加。

**验收**：
- 开启开关后，刮削走新管道，字段溯源、来源尝试记录、快照缓存均生效。
- 关闭开关行为与现版本一致（回归安全）。
- 配置里的来源开关/内容路由/字段优先级真正影响抓取结果。

### 阶段 2：在线搜索结果具备详情与动作

**目标**：搜索结果可点开详情、可"刮削到本地"、可"在浏览器打开"，补齐文档 3.4。
**范围**：`VideoView.SearchPage` 的结果卡片，以及详情弹窗/页。

**方案**：
- 给 `RenderOnlineResults` 的每张结果卡片加 `MouseLeftButtonUp` → 打开 `OnlineVideoDetailView`（新建，或在 `VideoView` 内嵌详情面板）。
- 详情展示：封面、标题、原题、演员、标签、简介、预览图、源链接。
- 动作按钮：
  - **刮削到本地**：用户选择本地目录 → 用在线结果元数据创建 `VideoItem` → 触发阶段 1 的新管道刮削补全。
  - **在浏览器打开**：`Process.Start` 详情页 URL。
- 统一在线搜索实现：把 `OnlineVideoView` 的平行逻辑合并进 `VideoView.SearchPage`（或反之），删除孤儿代码。

**验收**：
- 点结果卡进入详情；"刮削到本地"能落地并触发刮削任务；"浏览器打开"可用。
- 只保留一套在线搜索实现。

---

### 阶段 3：多源在线切换做实

**目标**：`VideoSearchPanel` 的源选择器不再是摆设。
**方案**：
- `OnlineVideoView.SwitchSource`（或合并后的统一入口）按 `sourceId` 从 `App.Services.GetServices<IVideoSource>()` 选取对应源。
- 当前仅 MissAV 注册；后续若接入更多 `IVideoSource`，按契约注册即可，无需改 UI。
- 切换源时重置分页与结果，刷新 SourceTabs 高亮。

**验收**：注册 N 个 `IVideoSource`，选择器即可切换 N 个源的搜索结果。

### 阶段 4：演员档案页 `ActorProfileView`

**目标**：详情页点演员不再只是筛选，而是打开档案页（文档 P2）。
**方案**：
- 新建 `ActorProfileView`，入口为详情页 `ActorChips` 点击（替代 `FilterByActor` 的全量跳转，或加"查看档案"入口）。
- 数据来源：`VideoActorMerger.MergeAsync(actorName)`（阶段 1 已注册）+ `VideoLibraryService.Query(actorFilter=name)` 取本地作品。
- 展示：头像/别名、基本信息、本地作品卡片网格、在线资料来源链接。
- 头像优先 `VideoActorMetadata.ImageUrls`（如 GFriends 的 GitHub 头像）。

**验收**：点演员进入档案页，能看到本地作品与在线资料；本地作品卡可点回详情。

---

### 阶段 5：缓存管理视图 `VideoCacheView`

**目标**：替代仅有的"清除缓存"按钮，提供可见的缓存概览与精细管理。
**方案**：
- 新建 `VideoCacheView`（可嵌入设置或作为独立页）：
  - 快照缓存条数/大小、图片资源条数/大小、缓存目录。
  - 操作：清除全部快照、清理无引用图片资源、打开缓存目录。
- 底层复用已实现的 `DiskJsonSnapshotCache` / `DiskVideoResourceStore`。
- 引用检查函数遍历 `VideoLibraryService.Items` 的 `CoverPath`/`PosterPath`/`PreviewImages`。

**验收**：缓存概览数字与磁盘一致；清理操作生效且不影响在用封面。

---

### 阶段 6：详情页字段补齐

**目标**：把已抓取但未展示的数据呈现出来。
**方案**：
- **短评（Reviews）**：`VideoView.RenderDetail` 内填充 `ReviewHost`（后端已存 `item.Reviews`）；空时隐藏"短评"标题。
- **审查类型（CensorType）**：在 `MetaText` 中加入有码/无码标识（侧栏已可筛选，详情未显示）。
- **多源来源链接**：`SourceUrls` 现有只显示 javbus/javdb，扩展为列举全部已知来源链接。

**验收**：有短评时显示；详情可见审查类型；来源链接完整。

---

### 阶段 7：推荐页海报点击导航

**目标**：`VideoRecommendView` 点海报应进详情而非打开资源管理器。
**方案**：`OnDetailRequested` 改为通过 `ShellNavigator`/主窗口导航到本地详情，复用 `VideoView` 的 `DetailRequested` 机制；无法定位本地项时再降级为打开目录。
**验收**：点推荐海报进入对应本地视频详情。

- **DI 实例唯一性**：`ScrapeReportService`、`VideoScrapeTaskQueue` 必须单例且被引擎与 UI 共享，否则报告/任务读不到数据。
- **新旧引擎回归**：阶段 1 务必保留旧 `ScrapeAsync` 默认路径，开关未开时行为零变化。
- **文档失真**：`VIDEO-FRONTEND-GAP-ANALYSIS.md` 写于 .NET 9 时代且含虚构源清单，本计划以实际代码为准；建议本计划落地后废弃旧文档。
- **孤儿代码**：阶段 2 必须合并 `OnlineVideoView` 与 `VideoView.SearchPage`，否则会继续分裂。
